Case Study

QueueBuster Web Application Redesign

A complete redesign of the QueueBuster POS web app — solving speed, navigation, and usability issues across 11 modules with 100s of wireframes and a full design system.

Company
QueueBuster
Year
2021
Role
Product Designer
Platform
Web (SaaS)
Scale
11 Modules

Overview

💻 Introduction

This case study is about redesigning the web application of QueueBuster point of sale solution. 100's of wireframes and I don't know how many artboards I might have created during this project. This is my only project of this scale. To keep the case study as short as possible, I have included only the important ones due to the vastness of the project.

What is POS?

Point of sale is a place where the customer gets billed for the product or services he/she bought. A normal thing which happens in a store. A POS can have a computer or any electronic device which can generate a bill and can add the taxes and charges for the products bought.

What QueueBuster is doing?

QueueBuster provides an android platform replacing the old way of using laggy computers with small to large compact devices.

QueueBuster provides an Android App and Web App. The Android app can be installed on handheld, tablet, desktop POS devices for billing, inventory, and other operations. QueueBuster has customized solutions targeting Retail Business, Restaurant Business, Grocery Stores, Spa and Salon, and more.

QueueBuster App installed in POS devices

Main features of QueueBuster:

  1. Catalog Management to store product information with SKU, prices, taxes, charges, and other information.
  2. Inventory Management to maintain the desired stock level of products or services.
  3. Billing Solution to generate bills from the device.
  4. Various Payments Options like wallets, cash, card, UPI, cheque, etc.
  5. Reports to analyze the performance of the business.
  6. eStore to sell products online.

and more…

Problem Space

1️⃣ Defining the problem / Why Redesign Web app?

Apart from the visual change as the product looked old, it was slow for the customers while using the product and there were a lot of usability problems.

Goal 1: We needed a faster application.

Consider a super chain like Big Bazaar, Walmart or any other. These chains can have more than 50 stores and these 50 stores can have 50,000+ products. All these products can have name, prices, taxes, charges, etc. With lots of data our product was slow and annoying to use.

Goal 2: To improve Navigation.

We had 11 modules with lots of options and features inside it. Navigating between them was a cumbersome process in the old architecture.

Goal 3: To improve Usability across the system especially in Order Detail, Tables, Product Catalog, etc.

The web app mostly had tables, forms etc. and these needed a great attention with keeping usability in mind.

Phase 2

2️⃣ Ideation and Prototype Phase

After defining what we were planning to solve, we started exploring the products of payment companies, POS companies, inventory management companies. We were not just going to redesign the UI, but we were making architectural changes as well.

Performance

⚡ To solve Goal 1: Faster Application

  1. ReactJS was chosen to have a better interactive UI as ReactJS efficiently updates and renders the right components when data changes.
  2. As our main goal was to minimize the loading time, we went further on to changing the typography to System Font (0ms loading time) avoiding FOIT, FOUT. Our customers mostly would be using Windows or Apple laptops Segoe UI, San Francisco were great for us. Although, it does not take a lot of time to load fonts from servers we were saving time there.

Navigation

🧭 To solve Goal 2: To improve Navigation

We had too many options in the sidebar which were equally important, but scrolling between them was not a very good experience. We decided to use the same hamburger menu navigation in the sidebar but by dividing everything into 6+ modules. Two-panel selectors are always the best for users, as their tasks require them to switch between overall items and specific content multiple times while they're performing a task with minimal cognitive expenditure.

Older Navigation
Newer Navigation

Why newer navigation was better:-

  1. Easy navigating to all the options and features.
  2. Most of our targeted customers would have windows laptops, which is known for its bad experience with the touchpad. We minimized the use of the scroll function in the touchpad in order to have a better experience while navigating through the menu.

Usability

🎯 To solve Goal 3: To improve usability across the system

80% of the web app consist of tables, form, order information or something similar to these.

Tables

📊 1. Tables

Tables were the best option to visualize our data, but we were showing lots of fields in a table. The user had to scroll horizontally to see all the fields, sometimes the user had to scroll for like 5 sec in order to see a specific field or report or data. We had customers who said, “they never knew that it was scrollable.”

New-Horizontal scroll in table

2. Showing a table with a filter

Showing a table with a filter was also a major concern in our current design. We wanted the table to be visible in the first place.

Order Detail

📋 3. Order Detail

Order Detail page was the most difficult one for our customers. It showed all the information in table format which was really a bad experience for the user. We planed out that we wanted to have something similar to the physical bill/invoice format.

Old UI
New UI

Product Form

📦 4. Create Product

Create Product form which was the most important one. Although it needed some UI changes, more than that we introduced an attribute system so that it can handle different industries like Retail Business, Restaurant Business, Grocery Stores, Spa and Salon, and more.

Attributes, that a product can be differentiated from one another and would be easy in managing inventory as well.

We had different subscription plans for QueueBuster POS solution, this new create product was made on keeping that in mind.

Reflection

3️⃣ My Takeaway

This project helped me understand how to design in scale. When I started with UI, I was skeptical about the background grey color in the web app. The white color looks modern but when I tested all the UI with different shades of grey and white background in over 5–10 different laptops from cheap windows to high-quality screens. I found that the boring grey was far better than the white background in terms of visibility of text, fields, tables, etc.

Working on this project was overwhelming due to the sheer amount of UI which needed to be designed with other projects in line. I created the entire design library for all the components, I am not sure if I can call it a design system. At the moment I am trying to do a cognitive walkthrough and heuristic evaluation with the product.

The design process is different in every company. I believe all the references we take from good sources(google, apple, uber, etc.) are already an outcome of the design thinking process. I try to understand those tried-tested-successful patterns and use them according to requirements. Tables, Forms, etc. components (more than 100 years of research or more than that) are the things that we cannot break and create something new to visualize the data. I decide when it's correct to visualize in the table and when not, it totally comes only after thoroughly understanding the product. I think designers do everything subtly without noticing that they had followed those design thinking steps in their minds. I learned the importance of usability and correct user flows with respect to the product. There is no point in making a great UI if the user is not able to reach a goal successfully. A collaborative effort with different designers, engineers, testers, project managers can help make a better product.

Thanks if you read this far:)

Quick Summary

QueueBuster Web POS Architecture Redesign

  • Scope: Complete overhaul of 11 enterprise modules across ReactJS web application.
  • Key Drivers: Application loading speed, complex navigation, table data density.
  • Target Verticals: Retail chains, Restaurants, Grocery, Spas & Salons.
🚀 Outcome: Reduced loading latencies while improving daily merchant operational speed.
Navigation Architecture

Two-Panel Navigation System

  • Cognitive Efficiency: Two-panel selector allows fast switching between core modules and sub-features.
  • Touchpad Optimization: Minimized vertical scrolling friction on standard Windows hardware.
💡 Innovation: Replaced long single-column scroll menu with structured 2-panel hierarchy.
Table Usability

Data Table & Filter Optimization

  • Scroll Affordance: Fixed hidden horizontal scrolling issues across multi-column reports.
  • Filter Hierarchy: Compact filter controls to keep table data above the fold.
📊 Design Impact: Enabled instant data scanning for multi-store managers.
Order Experience

Invoice-Style Order Detail Screen

  • Real-World Alignment: Transformed raw table data into a physical bill/invoice format.
  • Action Items: Clear status tags, refund triggers, and customer contact detail layout.
✅ Experience: Matched real-world cashier and manager mental models.
Product Catalog

Multi-Industry Attribute System

  • Attribute Support: Custom product attributes for size, color, serial numbers, and combo packages.
  • Tier Integration: Built-in support for QueueBuster subscription tier limits.
📦 Scalability: Single product engine supporting retail, F&B, and service verticals.
